## 6. Record-model readiness

- [ ] A stable ID format exists.
- [ ] One canonical Master Index exists.
- [ ] Status values are defined.
- [ ] Stage values are defined.
- [ ] Risk values are defined.
- [ ] Every active record has a next action.
- [ ] Every action has an owner.
- [ ] Every time-sensitive action has an absolute date.
- [ ] Every active record has a stable Hub URL.
- [ ] Detailed history is separated from current truth.
- [ ] Archive and deletion rules exist.
- [ ] A data dictionary exists.

## 10. Fictional-data acceptance test

Create one fictional record and test:

- [ ] Retrieval by stable ID.
- [ ] Correct Hub and folder links.
- [ ] Correct source citations.
- [ ] No unrelated record retrieval.
- [ ] Unsupported information marked Needs confirmation.
- [ ] Meeting brief follows the template.
- [ ] Draft follow-up is not sent.
- [ ] Proposed change shows Before, After, and Why.
- [ ] No write occurs during read-only mode.
- [ ] Approved low-risk write is verified.
- [ ] Provider switch does not break the record model.

## 13. Advisory output

A completed professional assessment should produce:

1. executive summary;
2. current-state architecture;
3. information and workflow maps;
4. canonical record recommendation;
5. privacy and permission findings;
6. prioritized AI use cases;
7. provider and connector recommendation;
8. pilot design;
9. measurement plan;
10. technology roadmap and budget range.

Do not include confidential business data in a public repository issue. Use a private channel for implementation discussions.
