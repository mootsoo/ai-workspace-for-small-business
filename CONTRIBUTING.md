# Contributing

Contributions are welcome when they improve the framework without weakening its provider neutrality, human-authority model, privacy boundaries, or evidence standards.

## Good contributions

- clearer small-business examples;
- provider-neutral templates;
- corrections to current official capability references;
- accessibility and readability improvements;
- fictional case studies from additional industries;
- stronger governance controls;
- migration guidance;
- Mermaid diagrams;
- translation proposals that preserve meaning;
- assessment improvements.

## Contributions that require extra care

- current ChatGPT, Claude, Google, MCP, n8n, or database capability claims;
- security and privacy recommendations;
- regulated-industry examples;
- licensing changes;
- code that writes to external systems;
- automation that changes canonical business state.

Use primary official sources for current product capability claims and include a verification date.

## Do not contribute

- real client, student, patient, customer, or employee data;
- private Drive URLs;
- email addresses without permission;
- credentials, tokens, connection strings, or recovery codes;
- copyrighted screenshots without permission;
- invented product capabilities;
- legal or compliance certification claims;
- marketing claims presented as measured evidence;
- provider-specific architecture presented as the only valid design.

## Framework invariants

A contribution should preserve these principles:

1. Business-controlled systems hold operational truth.
2. AI providers are interfaces, not canonical databases.
3. Stable identifiers support portability and migration.
4. Retrieval uses the minimum necessary context.
5. Facts, decisions, actions, suggestions, and uncertainty are separated.
6. Consequential actions remain human-controlled.
7. Complexity is added only when operating evidence justifies it.
8. Fictional or non-sensitive data is used for public examples and acceptance tests.

## Pull request expectations

Describe:

- what changed;
- why it improves the framework;
- which sources support current capability claims;
- privacy or governance impact;
- files changed;
- validation performed;
- any unresolved limitation.

Keep examples fictional and provider-neutral unless the file is explicitly a provider-specific setup note.

## Discussions and inquiries

Do not post confidential business information in issues, pull requests, or discussions.

For private advisory or implementation inquiries, contact Tsolmon Khudulmur through LinkedIn or GitHub before sharing sensitive material.
